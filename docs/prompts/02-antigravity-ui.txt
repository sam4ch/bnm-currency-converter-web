Вместе с UI исправь найденные просмотром первой реализации ошибки и запиши их в REPORT.md:
- BnmXmlParser использует NumberStyles.Any: это может трактовать запятую как группировку и принимать экспоненту. Для XML принимай только официальный числовой формат с точкой, без группировки/экспоненты; проверь синтаксис до decimal.TryParse.
- Пустой HTTP body или валидный ValCurs без Valute — отсутствие публикации: верни null, чтобы RateLookupService искал прошлую дату. Неверный непустой XML остаётся ошибкой с остановкой поиска. Не превращай ответ только с неподдерживаемыми валютами в фиктивно успешный набор из одного MDL.
- У HttpResponseMessage в BnmRateClient нужно гарантированное Dispose; токен тайм-аута должен охватывать чтение тела. Не проглатывай внешнюю отмену CancellationToken.
- Чтение JSON-кэша проверяет schema Version, непустой SourceUrl, timestamp, единообразие дат записей и базовый MDL=1; испорченный документ должен возвращать cache miss, а не исключение или выдуманные исправленные значения. Нельзя молча подменять плохой Entry.PublicationDate датой корня и добавлять MDL в повреждённый сохранённый кэш. Для XML добавление MDL=1 корректно.
- Запись кэша валидирует RateSet до замены хорошего файла. Нужны валидные даты/метаданные/MDL=1. Конструкторы не всегда гарантируют эти свойства.
- Проверку наличия выбранных валют выполняй до сохранения нового RateSet, чтобы непригодный для расчёта ответ не вытеснил рабочий кэш.
- AmountValidator и JS должны иметь одинаковую грамматику. Принимай цифры с одним необязательным десятичным разделителем и дробью из 1–4 цифр; не принимай ведущий плюс, '.5', '1.' и группировку. Внешние пробелы можно обрезать одинаково на обеих сторонах; внутренние пробелы запрещены.
- Для безопасного разбора XML запрети DTD/внешние сущности и ограничь разумно размер документа. Убедись, что ошибки преобразования огромных чисел/кэша не роняют страницу.

Используй file tools, не требуй глобального обхода разрешений. Если shell недоступен, укажи это честно и продолжай писать код; оркестратор выполнит сборку/проверку. Не останавливайся на описании плана, создай все реальные файлы UI.

Визуально: законченная, аккуратная веб-страница конвертера валют — светлый фон, тёмный читаемый текст, один фиолетовый/индиго акцент, крупное поле суммы и результата, карточка с формой, компактные бейджи источника и даты. Русские подписи и понятные состояния. Адаптивная вёрстка на телефоне и ПК, нормальные отступы, видимый focus для клавиатуры. Никаких внешних шрифтов/CDN/Bootstrap/jQuery — страница должна оставаться удобной без внешнего интернета. Достаточно собственного CSS/JS и локального SVG-фавикона.

Форма: сумма (type=text, inputmode=decimal, чтобы принимать и точку, и запятую), исходная/целевая валюта MDL/EUR/USD/RON/GBP, дата по умолчанию сегодня в Кишинёве, кнопка «Конвертировать», кнопка обмена валют. Сумма изначально пустая и кнопка disabled, обязательные поля всегда валидируются и на сервере. Механизмы Razor Pages antiforgery не отключай. Имена HTML id для устойчивой проверки: amount, sourceCurrency, targetCurrency, rateDate, convertButton, swapCurrencies. Результат id=conversionResult, ошибки/предупреждения role=alert или aria-live. Кнопка подтверждения кэша id=useCachedButton появляется только при подходящем сохранённом наборе.

Подключи реальный Core/Infrastructure. Не дублируй расчёт валют в браузере. Кнопка disabled для пустого/неправильного ввода и пока идёт запрос; loading-state работает при submit, при новом запросе старый результат не выглядит новым. Обработчики сохраняют введённые значения и выводят русские ошибки без stacktrace.

При одинаковых валютах: точная исходная сумма, текст «Курс не требуется», никакой выдуманной даты/времени/источника получения. При нормальной конвертации: реальная дата курса, выбранная дата, source URL BNM, время получения и предупреждение о предыдущем дне/кэше. При нет сети: объяснение, а если кэш подходит — предложение использовать его с датой, только после явного клика. Повторный POST подтверждения должен заново прочитать и проверить серверный кэш и не повторять ненужный HTTP. Не принимай скрытые курсы из браузера за доверенные данные.

Для настроек сети и кэша используй ясные appsettings-ключи, сохрани официальный BNM endpoint по умолчанию. Путь кэша относительно ContentRoot должен переживать перезапуски, папка App_Data уже исключена из Git. Сообщение об ошибке записи кэша не должно убирать успешный результат. Обработай отсутствие курса, неверный XML/HTTP и неподходящий кэш через состояния Core.
