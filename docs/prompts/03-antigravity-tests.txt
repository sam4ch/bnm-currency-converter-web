Этап тестирования лабораторной №3. Репозиторий CurrencyConverter-Lab3, ветка tests/currency-converter создана после слияния PR реализации. Прочитай актуальный код Core/Infrastructure, .specify/memory/constitution.md, specs/001-currency-converter/spec.md, tasks.md, contracts и docs/ASSIGNMENT_REQUIREMENTS.md.

Реализуй реальные xUnit-тесты T020–T027 в tests/CurrencyConverter.Tests/Unit и подходящие Fixtures/Helpers. Не меняй ветку, не делай commit/push/merge; оркестратор запускает dotnet test и сохраняет коммиты. Не исключай падающие проверки и не подменяй ожидания значениями из реализации. Каждая проверка должна доказывать договорённое поведение; тестирование дат должно проверять правила, а не лишь наличие поля DateOnly.

Обязательное покрытие:
- BnmXmlParserTests: реальный формат ValCurs/Valute, EUR/USD/RON/GBP + добавленный MDL=1; Nominal > 1; дополнительные валюты; пустой body/ValCurs без записей возвращает отсутствие публикации; повреждённый XML, DTD/внешняя сущность, отсутствующие дата/Value/Nominal, дубликат, нулевой/отрицательный курс/номинал, экспонента/группировка/запятая вместо официальной точки — отвергаются. Не подключаться к реальному BNM.
- CurrencyCalculatorTests: известные фиксированные прямой/обратный/кросс-расчёты с Nominal > 1; AwayFromZero на точном midpoint (например 1.005), не банковское округление; сохранение точности до конца; overflow.
- AmountValidatorTests: приём "10.50" и "10,50", минимума "0.0001", лимита "1000000000000"; отклонение null/empty/letters/zero/negative/больше лимита/5 знаков дроби/внутренних пробелов/группировки/экспоненты/нескольких разделителей/ведущего плюса/".5"/"1." и переполнения. Внешние пробелы обрабатываются по контракту валидатора.
- RequestValidatorTests: допустимые валюты, неподдерживаемая/пустая, отсутствующая и будущая дата. FixedClock для границы суток Кишинёва; при необходимости тестировать ChisinauClock через внедряемый источник времени или прямо правила IClock, не изменять системные часы.
- RateLookupTests: запрошенная дата, ближайшая предыдущая, BNM вернул предыдущую дату, исчерпание 31 предыдущего дня; некорректная будущая дата ответа; network/timeout/format error немедленно прекращает поиск (проверить число вызовов). HTTP test-handler возвращает предсказуемые ответы, без реальной сети.
- ConversionServiceTests: одинаковые валюты возвращают исходные четыре дробных знака и не вызывают ни cache, ни source, metadata null; offline без кэша понятная ошибка; offline с кэшем сначала только CacheConfirmationRequired без результата, после подтверждения — правильный расчёт, metadata и warning. Кэш позже requestedDate и отсутствие выбранной валюты запрещены; подтверждение не повторяет запрос в сеть. Ошибка записи кэша не отменяет успешный результат.
- JsonCacheStoreTests: временные папки на каждый тест, запись и чтение НОВЫМ экземпляром (перезапуск), отсутствие/повреждённый JSON/плохие metadata/version/MDL/даты отклоняются без падения; плохой RateSet не заменяет хороший файл; несколько конкурентных записей оставляют целый проверяемый документ. Не использовать рабочий App_Data пользователя. Созданные собственные временные папки можно очистить после теста, не трогай реальные данные.
- BnmRateClientTests: fake HttpMessageHandler для корректного XML, HTTP error, cancelled/timeout, nullable publication; уважение внешнего CancellationToken. Никакого реального ожидания 10 секунд для каждого теста и никакой сети.

UI/mobile/keyboard-проверки остаются отдельными M001–M007, не выдавай их за xUnit. Не отмечай их выполненными по факту существования Razor-файлов.

Дополнительные замечания ревью для настоящих regression-тестов и исправлений (если подтвердятся): отсутствующее поле version не должно автоматически считаться "1.0"; Entries:[null] и RateSet/entries неверного типа должны считаться cache miss, не падением. CancellationToken не глотать в кэше/оркестрации и не превращать в успешный результат или предупреждение. Проверить ответы с единственным MDL с неверным курсом и повреждёнными timestamps. Граница исторического поиска: возвращённая BNM дата тоже должна входить в 31-дневное окно; DateOnly.MinValue не должна давать AddDays underflow. Напиши проверяющие поведение тесты, затем минимально исправь подтверждённые ошибки исходников, документируя их. Не подгоняй ожидания к дефектам.

Если shell недоступен, всё равно создай файлы через file tools. Оркестратор сам запускает dotnet test. Не утверждай, что тесты прошли до реальных результатов.
